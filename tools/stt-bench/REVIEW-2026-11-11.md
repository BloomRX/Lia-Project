### 6.1 Sintoma

```
PS J:\Lia-Project\tools\stt-bench> .\run-stt-bench.bat -Setup
== Interpretador

[erro] Nao foi possivel executar o Python selecionado.

Installing Python 3.12.10. ... Python 3.12.10 will be launched by python3.12[-64].exe
PS> py -3.12 --version
Python 3.12.10

PS> .\run-stt-bench.bat -Setup
== Interpretador
   python: ...\py.exe -3.12
  File "<string>", line 1
    import sys; print(%d.%d % (sys.version_info[0], sys.version_info[1]))
                      ^
SyntaxError: invalid syntax
```

### 6.2 Causa

**D18 — aspas duplas removidas em argumento de executável nativo.** O
PowerShell 5.1 remove aspas duplas ao montar a linha de comando de um `.exe`.
A sonda era:

```powershell
@('-c', 'import sys; print("%d.%d" % (sys.version_info[0], sys.version_info[1]))')
```

e chegou ao Python como `print(%d.%d % (...))`.

**D19 — `py.exe` existir era tratado como `py -3.12` existir.** O resolvedor
devolvia o primeiro achado sem testar, então o erro real ("runtime não
instalado") virava uma mensagem genérica.

### 6.3 Correção

| Defeito | Correção |
|---|---|
| D18 | a sonda passou a não ter aspas: `print(sys.version_info[0], sys.version_info[1])`, e a saída `3 12` é lida por regex |
| D19 | `Resolve-Python` testa `py -3.12`, `py -3`, `python.exe` e `.venv` em ordem; usa o primeiro que **executa** e informa 3.12+; cada descarte é impresso com o motivo |
| D19 | mensagem final aponta `py install 3.12` |
| — | `.venv` criado com Python antigo agora é recusado com instrução de apagar |

### 6.4 Regressão

`PowerShellStaticTests` (6 testes) verifica, sem executar Windows:

- ASCII puro; delimitadores balanceados; sem `?.`/`??`;
- sem splatting inline;
- **nenhuma aspas dupla em linha com `'-c'`** (o bug exato);
- a mensagem contém `py install 3.12`.

Total: **68 testes**, `Ran 68 tests — OK`.
